## 2. A fumaça

`scripts/validacao/validar-fumaca.mjs`, chamado por `validar.sh fumaca`, que roda a camada build
(o mapa das Server Actions sai do build de produção), sobe o `next start` e roda o roteiro.

- Tudo o que cria leva `VALIDA-FUMACA-<ts>` e é apagado no fim, inclusive quando um passo falha.
  Se a rodada morrer, o `verificar-sobras.mjs` acha o que ficou.
- A fumaça fica **fora** da rodada completa (`npm run validar` não a roda), porque as sete camadas
  já cobrem tudo o que ela cobre.
- **Mecanismo compartilhado:** o código que chama Server Action por HTTP (o mapa de ids do build,
  o cookie da sessão e a leitura da resposta) saiu de `validar-escrita.mjs` para
  `scripts/validacao/actions-http.mjs`, e as duas camadas importam dali. A rodada de fechamento
  prova que a escrita continua igual.

| Parte | Quando roda | O que roda | Segredos |
|---|---|---|---|
| `rapido` | todo push na `main` e todo pull request | estático, unitário e build (~2 min) | nenhum |
| `completo` | botão "Run workflow", só no repositório com a variável `VALIDAR_GC_DEV=sim` | escolha: `fumaca` (padrão, ~2 min) ou `completo` (as sete camadas, ~25 min) | 8, listados no cabeçalho do arquivo |

- **Uma rodada por vez:** a parte `completo` usa um grupo de concorrência.
- **Rastros:** ela guarda screenshots e logs por 14 dias.
- **Sobras:** ela não apaga as de outra rodada, para não atropelar uma rodada local.
- **Chrome:** o `validar.sh` aceita `CHROME_FLAGS`; no runner vai `--no-sandbox`.
- **Simulação local:** a parte `rapido` rodou numa cópia limpa, sem `.env.local` e com
  `pnpm install --frozen-lockfile`: 397 casos e 65 rotas. A parte `completo` só se prova no
  GitHub.
